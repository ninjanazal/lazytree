1 · The idea in plain words ^pgr0011

📜 Rows are commits ^pgr0016

git log prints commits newest first, every
commit before its parents. Each row is one commit. ^pgr0017

🛤 Columns are lanes ^pgr0021

A lane is a vertical line reserved for a line
of history. Lane 0 is the leftmost. ^pgr0022

📌 Parents reserve lanes ^pgr0026

When a commit is placed, it books a lane for
each parent that has none yet. ^pgr0027

➡ First parent stays ^pgr0031

The first parent inherits the commit's own
lane, so the main line stays straight. ^pgr0032

🔀 Merges open lanes ^pgr0036

Every extra parent gets a new lane: the lowest
free one, or a brand-new one on the right. ^pgr0037

♻ Lanes are recycled ^pgr0041

When nobody continues a lane, it goes back on
the free list, so the graph stays narrow. ^pgr0042

3 · The bookkeeping (Layouter) ^pgr0143

🗺 laneOf ^pgr0148

map[hash] → lane
which lane each commit is (or will be) drawn in.
Set when a child books a lane for its parent. ^pgr0149

♻ freeLanes ^pgr0153

sorted list of recycled lanes
allocLane takes the lowest; freeLane inserts
in order, so low lanes are reused first. ^pgr0154

📍 activeLanes ^pgr0158

map[lane] → hash it is waiting for
lanes still open below the current row;
used for the graph width and drawing. ^pgr0159

internal/graph/layout.go (simplified) ^pgr0161

for each commit c (newest first):
    lane = laneOf[c]  or  allocLane()          # step 1: where do I go?
    for j, p in parents(c):                    # step 2: book my parents
        if p has no lane: laneOf[p] = (j == 0 ? lane : allocLane())
        activeLanes[laneOf[p]] = p
    if lane not in parent lanes: freeLane(lane)  # step 3: nobody continues me
    emit GraphNode{Lane, Parents: parent lanes, Color: lane % palette} ^pgr0165

5 · Why it is fast ^pgr0190

Incremental by design ^pgr0194

The Layouter keeps laneOf / freeLanes / activeLanes between calls, so each new page of 500 commits costs O(page), not
O(everything so far). Measured: 108k commits laid out and rendered in ~1.2 s total. Preconditions: commits arrive newest first,
children before parents, append only (exactly what git log streams). ^pgr0195
